FlexDoc 3.3.1 · In progress1/2

Run API requests from the service network, not just the browser.

FlexDoc 3.3 expands controlled API-host execution across supported native runtimes. When a serving adapter advertises a real host executor, ordinary interactive API Client sends prefer the API host so the same canonical request workspace can reach approved internal or browser-limited targets without creating a second client. Reusable collection and headless execution remain direct by default unless host semantics are explicitly selected or required.

New in 3.2 · Headless Runner

Run the same API Client workflows locally and in CI.

Export one saved request, a folder subtree or a whole collection with its active environment. flexdoc run executes that portable, history-free artifact through the same request builder, auth inheritance, variables, scripts and tests used by the workspace.

flexdoc run ./pets.flexdoc.json --report ./flexdoc-report.json

Portable artifacts

Request, folder and collection exports preserve the scoped workspace and selected environment without copying browser History into CI.

Canonical execution

The CLI reuses the workspace Runner and executor, keeping request order, variable mutations, inherited auth, pre-request scripts and response tests aligned.

Direct or advertised host transport

Ordinary Runner requests stay direct. --host consumes the serving backend's advertised host-execution contract when selected or required; it does not invent a second execute route.

CI evidence

Machine-readable JSON and report files capture request identity, executor, status, timings, tests and errors, with stop-on-failure and cancellation semantics matching the UI Runner.

New in 3.1 · Contract Validation

Validate the contract from inside the running backend.

On Express, Fastify, Hono and NestJS, FlexDoc 3.1 turns runtime discovery into structured operation-level findings. The backend produces the result once; Runtime Intelligence and the CLI consume the same contract view instead of re-deriving it from the document alone.

Runtime-only endpoints may be intentionally undocumented. Protect non-public docs before exposing runtime findings. Contract Validation reports drift and can fail CI by threshold; it does not intercept or block API requests.

Operation-level findings

Distinguish undocumented, unobserved, method-mismatched and verified duplicate registrations instead of reducing drift to a flat route list.

Backend-owned truth

The running Node adapter produces the validation result, so the renderer and automation see the same framework-aware evidence.

Partial discovery is explicit

When discovery cannot prove the whole route surface, FlexDoc preserves that uncertainty instead of manufacturing false mismatches.

CLI and CI consumer

flexdoc validate supports machine-readable JSON, custom headers/auth and configurable failure thresholds against the backend-produced result.

New in 3.3 · Backend Execution Expansion

Run interactive requests through the API host across supported runtimes.

When an integration explicitly enables host execution and advertises it to the renderer, ordinary interactive API Client sends prefer the API host by default. That gives the same request model access to approved service-network targets without turning FlexDoc into a generic proxy or inventing framework-specific clients.

API host preferred interactively

If hostExecution.available is true, ordinary interactive sends prefer the API host even when capabilities: []. Operators can set preferHostExecution: false when browser-direct should remain preferred.

Native runtime coverage

Node plus Spring/JAX-RS, FastAPI/ASGI, Go, ASP.NET Core, Axum, Actix, Rack/Rails, Plug/Phoenix, Laravel and Symfony integrations can expose docs-scoped host execution when explicitly enabled.

Fail-closed network capability

Exact-origin allowlists, metadata/link-local blocking, redirect and destination validation, bounded transports and the application's own auth/CSRF boundary constrain the server-side network path.

Reusable collection/headless execution remains direct by default unless host execution is explicitly selected or required. Advanced host-only capabilities remain runtime-specific and are advertised explicitly.

Important limits

  • Runtime Intelligence is off by default. Runtime-only routes can reveal intentionally undocumented endpoints, so protect non-public docs before enabling it.
  • If route discovery is incomplete, FlexDoc marks it incomplete instead of guessing. Documented-only differences are less certain in that case.
  • Contract Validation can fail CLI/CI by threshold on supported Node integrations. Runtime Intelligence remains observational and does not reject requests or validate request/response schemas.
  • OAuth client secrets entered in a browser are not confidential. Browser OAuth also depends on the provider allowing the required redirect and CORS behavior.
  • API Client scripts are trusted local JavaScript, not a security sandbox. Saved workspace secrets are stored as entered in the browser origin.
  • Runner artifacts can contain request credentials, collection variables and environment values. Treat them as sensitive configuration and do not commit them blindly.
  • Runner --header, --bearer and --basic flags authenticate the FlexDoc docs/host endpoint only; target API auth remains part of the saved request model.
  • History can contain tokens or other sensitive response data. It is limited to 100 entries and new stored response bodies are capped at 256 KiB.
  • API-host execution can reach server-side networks from the serving runtime. Keep allowedOrigins as narrow as possible, keep the docs and execute routes behind application authentication/authorization, and apply the application CSRF model where cookie auth is used.
  • NTLM/Negotiate can be preserved as imported auth state but is not executable unless a serving host explicitly advertises compatible support.
  • Swagger/OpenAPI 2.0 is not accepted; integrations should provide OpenAPI 3.x.
Architecture

One renderer. Many ways to ship it.

Framework adapters obtain the OpenAPI document and serve version-matched FlexDoc assets. Parsing, schemas, code generation and Try It stay in the shared renderer instead of being rebuilt for each framework.

Self-host it with your API

Renderer assets are packaged with the integration. Docs-route credentials are checked on the server and are not written into browser configuration. You control the API, docs route and deployment.

Keep API work local

Collections, folders, requests, variables, auth, scripts, tests and History can live in browser storage. Try It can move the current request into that workspace without making you enter it again.
