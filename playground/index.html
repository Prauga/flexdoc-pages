What the browser Playground can configure

Playground has two tabs. Documentation renderer accepts OpenAPI 3.0/3.1 and exposes the practical client-side renderer contract. API Client mounts ApiClientWorkspace directly and lets you configure its initial request, workspace behavior, variables, scripts and server inputs. Applying API Client settings remounts that preview so initial props take effect immediately.

Documentation renderer
  • FlexDoc host props: theme, manageTheme, and root customStyles
  • metadata/chrome: title, description, altDescription, version, locale, messages, tagGroups, favicon, logo, and footer
  • visibility/navigation: hideTopbar, hideDownloadButton, hideHostname, hideLoading, nativeScrollbars, and pathInMiddlePanel
  • expansion/schema presentation: expand, legacy expandResponses, defaultModelsExpandDepth, requiredPropsFirst, sortPropsAlphabetically, showExtensions, and showCommonExtensions
  • request/document display: showRequestHeaders, noAutoAuth, lazyRendering, scrollYOffset, suppressWarnings, and payloadSampleIdx
  • Try It: enabled, defaultServer, browser credentials, sibling API Client persistence key, and the React requestInterceptor hook
  • code samples: enablement plus ordered curl, javascript, python, go, and java languages
  • brand/styling: partial ThemeConfig, raw customCss, root customStyles, structured logo sizing/padding/background/clickability, footer links, and renderer message overrides
API Client workspace
  • ApiClientWorkspace: persistenceKey, pageMode, manageTheme, and controlled activeEnvironmentId
  • ApiClient: initialRequest, initialScripts, initial request/script tabs, theme, density, messages, and browser credentials
  • request bootstrap: method, URL, query rows, headers, content type/body, auth, and advanced body/request fields such as URL-encoded, multipart, binary and GraphQL state
  • variables: effective, collection, external, and environment maps
  • servers: OpenAPI serverOptions and initialServerUrl
  • React request interception represented in Playground as deterministic header injection
  • workspace persistence can be disabled entirely so applying initial configuration always starts from the configured state

Browser/backend boundary

  • runtimeIntelligence and Try It/API Client host execution are backend-advertised capabilities. Playground does not invent endpoints or capabilities that the browser does not own.
  • customCss, root customStyles, and logo are browser-owned renderer inputs. customJs is executed by the generated/standalone host page, not eval'd by the React Playground.
  • callback props such as request/draft/script/execution callbacks, resolveAuth, workspace handoff callbacks and environment mutation callbacks are application integration hooks rather than static configuration values.
  • API-host execution, mTLS/certificate choices, host cookie jars, Digest/Hawk/OAuth1/AWS SigV4 and private-network reachability require a backend host that explicitly advertises them.

The Advanced options panels intentionally accept JSON for nested typed structures such as tag groups, messages, ThemeConfig, footer links, OpenAPI server choices, request auth and variable maps. Invalid JSON is rejected before the preview is changed.
