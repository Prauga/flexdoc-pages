FlexDoc 2.9.9 · published workspace

A local API workspace built on the same request engine as Try It.

FlexDoc 2.9.9 adds collection and folder execution on the same canonical request engine as Send. The runner previews exact saved-request order and active environment, reports per-request progress/status/timing/tests/errors, supports Stop and stop-on-runner-failure, carries variable mutations forward sequentially, adds phase-aware scripting IntelliSense, groups run sessions in History and promotes History into a searchable full inspector with persisted response details.

2.9.9 execution workspace

Local-first, reusable requests

Postman Collection v2.1 and environment exports import through the browser into the same canonical workspace model, with compatibility warnings for unsupported behavior.
Collections, arbitrarily nested folders, saved requests, collection variables and named environments persist in origin-scoped IndexedDB.
Collection, folder and request auth can inherit or override Bearer, Basic, API keys and OAuth 2.0; OAuth supports manual tokens plus browser-compatible grant flows.
Run collection and Run folder use the same executor as Send, preview the exact saved-request queue and active environment, and show pending/running/pass/fail/cancelled/not-run state with status, timing, tests and script/transport errors.
Execution is sequential so collection/environment mutations flow into later requests. Stop aborts the active fetch; Stop on runner failure reacts to transport/script/test failure rather than HTTP status alone.
Trusted scripts get phase-aware flex.* IntelliSense with dot/Ctrl+Space completion, signatures/docs, live variable keys, assertion-chain help, Arrow navigation, Enter/Tab acceptance and Escape dismissal.
Completed runner requests are grouped by run/session metadata. Full History adds search/filtering, response headers/bodies, tests/logs, replay, deletion and preserved collection/folder provenance.
History remains bounded to 100 entries; new response bodies are capped at 256 KiB, older entries without response payload fields remain readable, and cancelled in-flight runner requests do not create partial rows.
Local data & execution
Saved auth values, collection/environment variables, scripts and History are stored as entered and are not encrypted by FlexDoc. Persisted response headers/bodies may contain tokens or PII. Scripts are trusted local JavaScript, not a sandbox. Nothing is sent until you press Send request or start a collection/folder run.
